## 11. User Support

## Key Points

#### 1. 🆘 User Support Types  
- User support includes quick reference, task-specific help, full explanation, and tutorials.  
- Help is problem-oriented and specific; documentation is system-oriented and general.  

#### 2. ✅ Requirements for User Support  
- Help must be continuously available concurrent with the main application.  
- Help content must be accurate and complete, matching actual system behavior.  
- Consistency is required between help system parts and paper documentation.  
- Help systems must handle errors correctly and behave predictably (robustness).  
- Flexibility allows users to interact according to experience and task.  
- Help should be unobtrusive and not prevent users from continuing work.  

#### 3. 🛠️ Approaches to User Support  
- Command assistance provides help on specific commands (e.g., UNIX man, DOS help).  
- Command prompts give usage info after errors, mainly for simple syntax mistakes.  
- Context-sensitive help adapts to the current user context (e.g., tooltips).  
- On-line tutorials guide users through basics in a test environment but can be inflexible.  
- On-line documentation is digital paper documentation, often enhanced with hypertext for browsing.  
- Wizards lead users step-by-step through complex or infrequent tasks, allowing backward navigation.  
- Assistants monitor user behavior and offer contextual advice but must be user-controllable.  

#### 4. 🤖 Adaptive Help Systems  
- Adaptive help uses knowledge of context, user, task, domain, and instruction to tailor help.  
- Challenges include knowledge requirements, control of interaction, and scope of adaptation.  

#### 5. 👤 User Modeling Approaches  
- Single generic user model (non-intelligent).  
- User-configured model (adaptable).  
- System-configured model (adaptive).  
- Quantification models user expertise on a scale.  
- Stereotypes classify users into categories.  
- Overlay models compare actual user behavior to an ideal expert model.  

#### 6. 🧠 Knowledge Representation Techniques  
- Rule-based: knowledge as rules and facts, interpreted by inference mechanisms.  
- Frame-based: knowledge stored in structures with slots, useful for small domains.  
- Network-based: knowledge represented as relationships between facts.  
- Example-based: knowledge implicit in decision structures trained to classify situations.  

#### 7. ⚠️ Issues in Adaptive Help  
- Initiative: deciding if user or system controls help interaction and interruptions.  
- Effect: determining what is adapted and what information is needed.  
- Scope: adaptation at application level or system-wide, with system-wide being more complex.  

#### 8. 🎨 Designing User Support  
- User support must be designed integrally with the system, not as an add-on.  
- Focus on content and context over technology.  
- Help request methods include commands, buttons, toggles, or separate applications.  
- Help display methods include new windows, full screen, split screen, pop-ups, and hint icons.  
- Effective help uses clear, familiar, consistent, and instructional language with summaries and examples.  

#### 9. 💻 Implementation Issues  
- Help can be implemented as OS commands, meta-commands, or application-specific.  
- Help data structures include single files, file hierarchies, or databases.  
- Resource constraints include screen space, memory, and speed.  
- Help systems must be flexible, extensible, support hard copy, and allow browsing.
