## 3. The Interaction

## Key Points

#### 1. 🤝 Interaction Basics  
- Interaction is communication between user and system involving input and output.  
- Key terms: domain (area of work), goal (desired outcome), task (actions to achieve goal).  

#### 2. 🧠 Norman’s Interaction Model  
- Seven stages: establish goal, formulate intention, specify actions, execute action, perceive system state, interpret system state, evaluate system state.  
- Execution/evaluation loop describes continuous user interaction.  
- Gulf of Execution: gap between user’s intended actions and system’s allowed actions.  
- Gulf of Evaluation: gap between system’s actual state and user’s perception of it.  
- Human errors: slips (correct goal, wrong action) and mistakes (wrong goal or misunderstanding).  

#### 3. 🔄 Abowd & Beale Interaction Framework  
- Interaction involves four components: user, input, system, output.  
- Interaction is translation between different "languages" of these components.  
- Problems in interaction arise from poor translation between user intentions and system responses.  

#### 4. 🖐 Ergonomics  
- Ergonomics studies physical characteristics of interaction to improve comfort, safety, and efficiency.  
- Examples: control arrangement, environment (lighting, noise), health (posture), use of color (red for warning).  
- Industrial interfaces differ from office interfaces in data type, environment, and speed of change.  

#### 5. 🎮 Interaction Styles  
- Common styles: command line, menus, natural language, question/answer dialogue, form-fills, spreadsheets, WIMP, point and click, 3D interfaces.  
- Command line suits expert users; menus reduce memory load by showing options.  
- Natural language is intuitive but ambiguous and hard to implement well.  
- Question/answer interfaces guide novices but have limited flexibility.  

#### 6. 🖥 WIMP Interface Elements  
- Windows: movable, resizable screen areas with scrollbars and title bars.  
- Icons: small images representing objects or actions; windows can be iconized.  
- Menus: visible options, often hierarchical; types include pull-down, pop-up, pie menus.  
- Pointers: graphical indicators controlled by mouse or keyboard.  
- Additional elements: buttons, toolbars, palettes, dialog boxes.  

#### 7. 🗣 Speech-Driven Interfaces  
- Speech recognition is improving but still inaccurate.  
- Robust dialogue requires system confirmation and error handling.  

#### 8. ⚠️ Error and Repair  
- Systems should help users detect and correct errors easily.  
- Example: booking system confirms inputs step-by-step to avoid misunderstandings.  

#### 9. 🌍 Context in Interaction  
- Interaction is influenced by social (competition, fear), organizational (rules, culture), and motivational factors (ambition, satisfaction).  

#### 10. 🎉 Experience and Engagement  
- Users must want to use systems, not just be able to use them.  
- Concepts: flow (balance between anxiety and boredom), zone of proximal development (tasks achievable with help).  

#### 11. ⚙️ Physical Design Constraints and Trade-offs  
- Constraints include ergonomic, physical, legal/safety, aesthetic, and economic factors.  
- Trade-offs are necessary when constraints conflict (e.g., button size vs. space).  

#### 12. 🔄 Fluidity and Affordance  
- Physical controls should reflect logical system state (affordance).  
- Controls may have inverse actions (e.g., twist controls for volume).  
- Spring-back controls provide tactile feedback and natural control.  

#### 13. 💡 Managing Value  
- People use systems only if perceived value exceeds cost (effort, money, time).  
- Value includes work efficiency, fun, or benefit to others; cost includes learning effort and money.  
- People heavily discount future value and cost, preferring immediate benefits.  
- Organizational value can be enforced by coercion, enculturation, or emergence.
