## 4. Task Abstraction

## Key Points

#### 1. 🎯 Task Abstraction Basics  
- Task abstraction translates specific domain questions into generalized tasks.  
- It involves identifying user actions and targets to form {action, target} pairs.  
- Task abstraction helps design visualization tools that work across different domains.

#### 2. 🏞️ Domain Characterization  
- Domain characterization includes understanding users, target domain, their questions, and data.  
- It must be specific enough to guide task abstraction effectively.  
- Domain questions are broken down into simpler abstract tasks.

#### 3. 🔄 Design Process Steps  
- Characterize the domain situation.  
- Map domain-language tasks to abstract tasks.  
- Identify or create suitable idioms or techniques for visualization.  
- Map domain-language data descriptions to data abstractions.  
- Identify or create suitable algorithms to support tasks.

#### 4. 🛠️ Actions in Task Abstraction  
- Actions include analyze, search, and query.  
- Analyze can be split into discover (explore) and present (explain).  
- Search types: lookup, locate, browse, explore.  
- Query levels: identify (one), compare (some), summarize (all).  
- Actions and query levels can be mixed independently.

#### 5. 🎯 Targets in Task Abstraction  
- Targets are the data elements or objects acted upon (e.g., distribution, trends, outliers, topology).  
- Domain jargon should be removed to create general target descriptions.  
- Task and data abstraction interact; task abstraction can lead to data transformation.

#### 6. 🔄 Iteration Between Task and Data Abstraction  
- Task and data abstraction require iterative refinement.  
- Initial passes at data and tasks are revised based on design needs.  
- This iterative process continues until suitable abstractions are achieved.
