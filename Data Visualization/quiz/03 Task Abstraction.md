## 4. Task Abstraction

## Questions

#### 1. What is the primary purpose of task abstraction in visualization design?  
A) To identify the types of data that support user tasks  
B) To create detailed domain-specific jargon for users  
C) To design algorithms without considering user needs  
D) To translate specific domain problems into generalized tasks  

#### 2. Which of the following are considered core components of task abstraction?  
A) Actions and targets  
B) Data types and user questions  
C) Domain jargon and user interface design  
D) Algorithms and visualization idioms  

#### 3. When characterizing a domain for visualization design, which factors must be considered?  
A) The group of users and their expertise level  
B) The specific questions or problems users want to solve  
C) The data available and its structure  
D) The programming language used to implement the visualization  

#### 4. Which of the following best describe the relationship between task abstraction and data abstraction?  
A) Data abstraction always precedes task abstraction in the design process  
B) Task abstraction defines what users want to do, while data abstraction defines the data needed to support those tasks  
C) Task abstraction sometimes requires transforming or deriving new data abstractions  
D) Data abstraction is independent of task abstraction and can be designed separately  

#### 5. In the context of actions within task abstraction, which of the following are valid examples of "search" actions?  
A) Identify, compare, summarize  
B) Discover, present, annotate, derive  
C) Lookup, locate, browse, explore  
D) Produce, enjoy, consume  

#### 6. How do "analyze," "search," and "query" actions differ in terms of user interaction with data?  
A) Analyze actions are only used by expert users, while search and query are for casual users  
B) Analyze focuses on consuming data, search on finding items, and query on determining data scope  
C) Search always requires prior knowledge of the target location  
D) Query actions involve identifying, comparing, or summarizing data subsets  

#### 7. Which of the following statements about targets in task abstraction are true?  
A) Removing domain jargon from targets helps create a more general vocabulary  
B) Targets are always individual data points, never groups or patterns  
C) Targets represent the objects or data elements users act upon  
D) Task abstraction can lead to changes in how targets are defined or represented  

#### 8. What does the iterative process between task and data abstraction typically involve?  
A) Ignoring domain-specific details to speed up design  
B) Continuously refining both tasks and data to better support user needs  
C) Revising data abstractions based on task requirements and vice versa  
D) Finalizing data types before defining any tasks  

#### 9. Which of the following pairs correctly illustrate {action, target} in task abstraction?  
A) Locate outliers  
B) Annotate algorithms  
C) Discover distribution  
D) Compare trends  

#### 10. Why is it important to map domain-language tasks to abstract tasks during visualization design?  
A) To avoid considering user questions and focus solely on data processing  
B) To ensure the visualization only supports one specific domain  
C) To systematically remove domain-specific jargon and clarify user goals  
D) To identify suitable visualization idioms and techniques that can be reused

## Answers

#### 1. What is the primary purpose of task abstraction in visualization design?  
A) ✓ To identify the types of data that support user tasks — Understanding data types is part of abstraction.  
B) ✗ To create detailed domain-specific jargon for users — Task abstraction removes jargon rather than creating it.  
C) ✗ To design algorithms without considering user needs — Algorithms are designed *after* understanding tasks and users.  
D) ✓ To translate specific domain problems into generalized tasks — This is the core goal of task abstraction.  

**Correct:** A, D


#### 2. Which of the following are considered core components of task abstraction?  
A) ✓ Actions and targets — These form the fundamental vocabulary of task abstraction.  
B) ✗ Data types and user questions — Data types relate more to data abstraction; user questions are domain-specific.  
C) ✗ Domain jargon and user interface design — Jargon is removed; UI design is separate.  
D) ✗ Algorithms and visualization idioms — These come after task abstraction in the design process.  

**Correct:** A


#### 3. When characterizing a domain for visualization design, which factors must be considered?  
A) ✓ The group of users and their expertise level — Essential for understanding who will use the visualization.  
B) ✓ The specific questions or problems users want to solve — Core to defining tasks.  
C) ✓ The data available and its structure — Data is fundamental to domain understanding.  
D) ✗ The programming language used to implement the visualization — Implementation detail, not domain characterization.  

**Correct:** A, B, C


#### 4. Which of the following best describe the relationship between task abstraction and data abstraction?  
A) ✗ Data abstraction always precedes task abstraction in the design process — They are iterative, not strictly sequential.  
B) ✓ Task abstraction defines what users want to do, while data abstraction defines the data needed to support those tasks — Accurate description of their roles.  
C) ✓ Task abstraction sometimes requires transforming or deriving new data abstractions — Iteration often leads to data transformation.  
D) ✗ Data abstraction is independent of task abstraction and can be designed separately — They are interdependent and iterative.  

**Correct:** B, C


#### 5. In the context of actions within task abstraction, which of the following are valid examples of "search" actions?  
A) ✗ Identify, compare, summarize — These are query actions.  
B) ✗ Discover, present, annotate, derive — These relate to analysis or production, not search.  
C) ✓ Lookup, locate, browse, explore — These are classic search actions.  
D) ✗ Produce, enjoy, consume — These relate to analysis or user engagement, not search.  

**Correct:** C


#### 6. How do "analyze," "search," and "query" actions differ in terms of user interaction with data?  
A) ✗ Analyze actions are only used by expert users, while search and query are for casual users — Analyze can be used by all user types.  
B) ✓ Analyze focuses on consuming data, search on finding items, and query on determining data scope — Correct differentiation.  
C) ✗ Search always requires prior knowledge of the target location — Search can be exploratory or browsing without prior knowledge.  
D) ✓ Query actions involve identifying, comparing, or summarizing data subsets — These are the three levels of query.  

**Correct:** B, D


#### 7. Which of the following statements about targets in task abstraction are true?  
A) ✓ Removing domain jargon from targets helps create a more general vocabulary — Essential for abstraction.  
B) ✗ Targets are always individual data points, never groups or patterns — Targets can be groups, patterns, or structures.  
C) ✓ Targets represent the objects or data elements users act upon — This is the definition of targets.  
D) ✓ Task abstraction can lead to changes in how targets are defined or represented — Task needs can influence target definitions.  

**Correct:** A, C, D


#### 8. What does the iterative process between task and data abstraction typically involve?  
A) ✗ Ignoring domain-specific details to speed up design — Domain details are important and inform abstraction.  
B) ✓ Continuously refining both tasks and data to better support user needs — Iteration improves design quality.  
C) ✓ Revising data abstractions based on task requirements and vice versa — Iteration is key to refining both.  
D) ✗ Finalizing data types before defining any tasks — Tasks and data abstractions evolve together.  

**Correct:** B, C


#### 9. Which of the following pairs correctly illustrate {action, target} in task abstraction?  
A) ✓ Locate outliers — Valid action-target pair.  
B) ✗ Annotate algorithms — "Algorithms" are not typical targets; annotation is an action but this pair is domain-specific and less general.  
C) ✓ Discover distribution — Valid action-target pair.  
D) ✓ Compare trends — Valid action-target pair.  

**Correct:** A, C, D


#### 10. Why is it important to map domain-language tasks to abstract tasks during visualization design?  
A) ✗ To avoid considering user questions and focus solely on data processing — User questions are central to task abstraction.  
B) ✗ To ensure the visualization only supports one specific domain — Abstraction aims for generality, not restriction.  
C) ✓ To systematically remove domain-specific jargon and clarify user goals — This clarifies and generalizes tasks.  
D) ✓ To identify suitable visualization idioms and techniques that can be reused — Abstract tasks guide technique selection.  

**Correct:** C, D
